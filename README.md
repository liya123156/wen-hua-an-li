# 文化案例工作台

丽兹行上海文化案例征集。四个目录：粘贴案例、案例库、案例评选、各店提交数量一览表。

## 简单提交

原文写清一个所属店面、一个推荐主题，粘贴故事后逐篇提交即可入库。无需额外确认表单，不强制填写人物、入职日期、事件日期、撰写人、行为点或达到300字。

可连续「新建一篇」保留多篇草稿；一次粘贴多篇时，根据重复的主题标题识别并提示拆分，分别点击「提交本篇」。店面、主题缺失或不明确时不能提交。修改已入库案例使用原记录，不增加提交数量。

## 案例库与提交数量

案例库按月份、价值观、门店及关键词查看。数量表包含21家门店、七个主题和行列合计，只按实际入库记录计数，与评选参考分及视频候选状态无关。未提交门店显示0；尚未读取案例时不展示虚假的0。

## 月会视频候选

依据用户提供的正式价值观解读与行为准则，对照正向行为、负向线索与原文证据。每主题最多推荐3篇，质量不足保留空缺。重点检查主人公、真实场景、关键选择、具体行动和实际影响是否能够构成月会视频叙事。人物与关键事实不清的案例可入库，但不会直接进入视频候选。

文本参考分为：文化准则对应25分、具体行动30分、实际价值25分、可学习性20分。候选需达到80分且通过叙事完整性条件。采用公开可读的文本规则辅助初筛，属于评选参考，不是大模型语义评审或事实核实；最终由负责人确认。

每篇可一键复制给BP / 撰写人的完整修改文字，含原文亮点、具体补充追问、人物贡献、结果核实、文化价值和视频素材 / 采访建议。也可按主题复制候选修改清单。不虚构事实、采访回答或对白。

## 数据与部署

复用既有Supabase项目的独立表 culture_cases_v1。所有读写均需内部邀请凭据，修改另需单篇凭据。邀请不进入源码或静态资源。RLS与列级权限保持原有保护。浏览器保存草稿与本设备的修改凭据，正式案例保存在共享数据库。

源数据库结构见 database/schema.sql，简化提交的增量变更见 database/simplify-submission.sql。已有案例内容不作批量修改。

无需安装依赖。npm test 验证分类识别、缺失和歧义阻断、多篇拆分、21×7数量合计、视频候选及可复制的修改文字。npm run build 生成静态 dist/。
